# Headroom — a browser talking-head experiment

A local browser app for a rigged MPFB / MakeHuman character styled as a floating head for a Pepper's Ghost display. A clean, non-gory neck cutoff hides the torso and clothes; runtime styling gives her a mint-green complexion, milky luminous eyes, small stitched scars, an asymmetric expression, and a separate Otohiko wig mesh framed by a cyan ghost halo, drifting lights, and animated base mist. The original ponytail is hidden; the CC BY 4.0 wig follows the default avatar's head bone, while the source MPFB GLB and its facial morph targets remain untouched. Her visitor persona is Bobby: a cheerful, gently spooky Calgary-area ghost who welcomes children with kind whimsy and light-hearted humor. She lived here about a century ago, when the city was smaller, and remembers being one of a few spooky neighbors; she shares that history only when visitors ask. She speaks with OpenAI TTS, while Rhubarb analyzes each phrase's **same WAV** and generates timed mouth cues for playback.

## First-time setup

Requirements: Python 3, `curl`, and `unzip`. For visitor capture on WSL, install camera/audio dependencies into the project-local `.venv`:

```bash
./scripts/install_conversation_deps.sh
```

This installs OpenCV, SpeechRecognition 3.17 or newer, and PyAudio. It does not install a browser or any person-detection model. Person detection is an optional external plugin; without one, motion wake and conversation still work, but person-presence wake and visitor crops are unavailable. Laptop speech output uses WSLg PulseAudio via `paplay`; if missing, install it with `sudo apt install pulseaudio-utils`.

Install the open-source Rhubarb Lip Sync command-line tool once (the official Linux release is about 84 MB; only the executable and English recognition data are installed outside this project):

```bash
./scripts/install_rhubarb.sh
```

## Run

```bash
./run.sh
```

Open **http://localhost:8766** in a browser on Windows or Linux. The plain URL is the clean kiosk display: once the avatar and services load, it automatically starts visitor mode, with no on-screen controls. Speech plays through the laptop's WSL PulseAudio output (`paplay`, normally WSLg's `RDPSink` to the current Windows audio output); the browser receives compact mouth-animation data and Rhubarb cues, but no speech audio. No Safari audio-unlock tap is needed. Add `?debug=1` to show touch controls and diagnostics; debug mode starts visitor mode off. Nova at Natural speed (0.94×) is the default, with relaxed conversational delivery. Stop the server with `Ctrl+C`; it shuts down capture and drains active speech work before exiting. Running `./run.sh` again gracefully replaces an existing Headroom server on that port, while refusing to terminate unrelated processes. To use a different port, run `PORT=9000 ./run.sh`. The default Rhubarb recognizer is `phonetic`, which keeps startup faster but can be less precise; use `RHUBARB_RECOGNIZER=pocketSphinx ./run.sh` to compare against PocketSphinx.

## GitHub Pages visual preview

The page automatically enters static visual-preview mode on `*.github.io`, or use `?preview=1` to preview it locally. This mode skips all `/api/` requests and displays the 3D avatar with orbit/zoom and credits; it does not provide the Python-backed speech, lip-sync, camera, microphone, or visitor features. To publish it, open the repository's **Settings → Pages**, select **Deploy from a branch**, choose `main` and `/(root)`, and save. GitHub Pages will publish the preview at `https://jbicks.github.io/floating-head/`.

## Optional external person detector

The MIT-licensed Headroom core ships with no detector implementation and does not install or import one by default. To add person detection, install a compatible adapter and its model dependencies into the same `.venv`, then set `HEADROOM_PERSON_DETECTOR=module:factory` before starting `./run.sh`. For example, `HEADROOM_PERSON_DETECTOR=my_yolo_adapter:create_detector ./run.sh` loads `create_detector()` from the separately installed `my_yolo_adapter` Python module. Headroom is compatible with YOLO-style detectors through this adapter seam, but no YOLO adapter, package, or model weights are included here.

An adapter factory must return an object with `detect(frame)`. Each call returns an iterable of `PersonDetection` values from `person_vision`, for example `PersonDetection(track_id=7, box=(x1, y1, x2, y2))`. Coordinates are pixel-space `(left, top, right, bottom)` in the supplied frame; track IDs must remain stable for the same visible person across nearby frames. The adapter should perform local inference only and must not upload frames itself. Headroom confirms tracks over two samples, bounds and refreshes crops, and sends crops only with a conversation turn. Check the adapter, detector package, and model licenses independently; for example, Ultralytics software is AGPL-3.0, while model weights may have separate terms. See [ATTRIBUTION.md](ATTRIBUTION.md). If no plugin is configured or it fails to load, the rest of visitor mode continues using motion wake without detector-based crops.

## Pepper's Ghost visitor mode (iPad display + laptop capture)

The iPad is a silent visual display only. Camera capture, motion wake (with optional person-presence wake), microphone listening, transcription, conversation, and speaker playback all run through the laptop's WSL backend; the browser receives animation envelopes and Rhubarb cues, not speech audio.

1. Connect the preferred Logitech BRIO to the laptop, then from **Windows PowerShell** run the hardware/network helper (Administrator is needed to bind a new USB device and configure the private Wi-Fi port proxy):

   ```powershell
   Set-Location '\\wsl.localhost\Ubuntu\home\<your-wsl-user>\3d_head_playground'
   .\run.ps1
   ```

   Replace `<your-wsl-user>` with your Linux username. If Windows blocks script execution, run `Set-ExecutionPolicy -Scope Process Bypass` in that PowerShell window, then retry; this only changes policy for that window. The launcher infers its WSL project directory from the checkout path; `-WslProjectPath` is available for nonstandard layouts.

   It prefers a connected Logitech BRIO, otherwise a USB camera that Windows/usbipd exposes; it attaches that camera to WSL and retries an active hardware preflight for a real camera frame, an openable microphone stream, and WSLg laptop audio. If a bridge does not come up, it stops with a diagnostic instead of silently launching a degraded visitor session. A saved-but-disconnected BRIO cannot be attached until its cable/USB connection is restored. On a Private Wi-Fi network, it also configures the iPad port proxy and prints the display URL.

2. After preflight, the helper starts `./run.sh` in WSL and stays in the foreground. Keep that PowerShell window open; press **Ctrl+C** there to stop Headroom. Once the server has started, open the helper's URL in Safari on the iPad. The clean display automatically starts visitor mode; no buttons or iPad audio gesture are required. For testing, add `?debug=1`: that page shows the monitor and touch controls but leaves visitor mode off until you tap **Start visitor mode**. The monitor reports camera/microphone readiness, local person-detector status, pending person crops, automatic visitor wakeups, recognized-turn count, saved image count, and TTS/lip-sync/laptop-audio readiness. **Reply ready** means a reply is queued; **speaking** means the laptop is playing it. Use **Greet now** to test without waiting for motion. The backend claims and plays each visitor reply on the laptop without waiting for an iPad request; a connected display receives mouth-animation events only. The display status endpoint records a low-volume heartbeat, so `logs/headroom.log` can show when polling pauses or resumes. The page reconnects after a server restart; speech continues even if it disconnects, although lip-sync is unavailable while the display is offline. Stopping visitor mode stops future capture/listening and lets a reply already in progress finish naturally.

Headroom prefers a Logitech BRIO camera and microphone, then a recognized built-in input, then the WSL system-default microphone. If the BRIO mic is not exposed to WSL, the system-default source (often WSL's `RDPSource`, following the Windows default input) is used. TTS plays through the WSL PulseAudio default output; this machine reports `RDPSink`, which routes through WSLg to the current Windows audio output. Run `./scripts/check_capture_devices.py` in WSL to inspect camera and microphone inputs. If an external person-detector plugin is configured, it samples the latest camera frame about once per second and must return stable person track IDs with pixel-space boxes. Headroom requires a track in two samples before queuing an anonymous person crop. Newly confirmed or refreshed person crops—at most one per track every 10 seconds, up to four per reply—are sent to OpenAI. A turn with no fresh crop is text-only; full-scene frames are not uploaded. Bobby's event context places her by a home's front door on Halloween, where children and families approach to trick-or-treat. She knows a candy bowl is in front of the display and frames it as a cheerful treat: she warmly invites each visitor to enjoy a couple of pieces and leave some for others, without sounding scolding; she is instructed not to claim she can see or count it, or to reveal when the hosts are away. When a visitor arrives, Bobby starts generating a very short, cheerful welcome immediately while the microphone listens concurrently. If a visitor begins speaking during generation, she discards the unplayed greeting and responds to them instead. The microphone closes before Bobby's speech plays, avoiding feedback from her speaker, then reopens afterward. The microphone is closed before Bobby's own speech plays, avoiding feedback from her speaker, then reopens afterward. Bobby keeps listening through quiet pauses while a visitor remains visible, with a five-minute safety limit; after visitors leave, two quiet listen windows end the interaction. If a visitor remains visible but two listen windows produce no usable speech, Bobby offers one gentle repeat prompt for the interaction, then keeps listening without repeating it. A subtle, eased head tilt and brighter eyes signal listening or considering a recognized reply; the halo and base mist softly pulse as Bobby listens, thinks, and begins speaking. Speech capture is calibrated once when visitor mode starts (rather than after each reply), accepts brief utterances down to about 0.18 seconds, and uses a 0.9-second pause as a tentative endpoint: transcription starts while the microphone continues listening. The ambient threshold can refresh every five minutes, but only while visitor mode is idle, with no recent person or motion for at least 10 seconds; it never forces recalibration during an interaction. If the visitor resumes before a transcript is accepted, the partial result is discarded and the added audio is included in a new transcription request. This may incur extra transcription usage; obsolete requests may still finish on OpenAI's side. Track IDs and crops remain in memory only, expire if unused, and are not used for identity recognition. If no detector plugin is installed or available, dialogue continues without person-detection crops. Leave `HEADROOM_PERSON_DETECTOR` unset to use motion wake only; set `HEADROOM_LOCAL_PERSON_DETECTION=0` to explicitly disable the plugin and all person-detection vision uploads. Configure model paths and other detector settings through the separately installed adapter's own documented options. Raw visitor audio is sent to OpenAI for transcription but is not saved. Recognized visitor transcript text is retained by default in private `logs/visitor_transcripts.jsonl`, rotated at 3 MiB with three backups; set `HEADROOM_SAVE_TRANSCRIPTS=0` before `./run.sh` to disable it, or remove the transcript log and backups with `rm -f logs/visitor_transcripts.jsonl*`. The person-crop JPEGs actually sent for visual context are also saved by default in `logs/vision_frames/` for validation. The latest 100 Headroom images are retained in a private local directory that the web server does not expose. Remove them with `rm -rf logs/vision_frames`, or set `HEADROOM_SAVE_VISION_FRAMES=0` before `./run.sh` to disable image saving. OpenAI usage charges apply to transcription, vision/chat, and speech. Because person crops are sent to OpenAI for visual context, tell visitors when vision is active and follow the event's consent requirements.

The Windows helper restricts iPad forwarding to the active Private Wi-Fi interface and `LocalSubnet`. Do not expose this unauthenticated local demo on a Public network or the internet. Rerun the helper after WSL or Wi-Fi addresses change.

The launcher prefers the OpenAI credential stored in Pi at `~/.pi/agent/auth.json`, falling back to `OPENAI_API_KEY` from the shell. Set `OPENAI_USE_PI_AUTH=0` to opt out of Pi auth and use only the environment key. The key is passed to the local Python server process; it is never written to this project or exposed to the browser. If running `python3 server.py` directly, set `OPENAI_API_KEY` in that shell first. Runtime output is mirrored to `logs/headroom.log` (private local file, excluded from Git; rotated on startup after 3 MiB, with three backups). It records device selection, mode transitions, saved snapshot paths, speech/TTS timings, and service errors—not transcript text, audio payloads, prompts, request bodies, or credential values. Recognized visitor text is stored separately in `logs/visitor_transcripts.jsonl`. JPEG snapshots are in `logs/vision_frames/`; use `ls -lt logs/vision_frames` to inspect them, `tail -f logs/visitor_transcripts.jsonl` to review recognized words, and `tail -f logs/headroom.log` to follow events. Set `HEADROOM_DEBUG=1` before `./run.sh` for throttled camera-frame diagnostics. Process resource sampling logs RSS/peak RSS, CPU, thread count, child-process count, and open file descriptors once per minute by default; override with `HEADROOM_DIAGNOSTICS_INTERVAL_SECONDS` (5–300 seconds). For Python allocation tracing during a diagnostic run, set `HEADROOM_PROFILE=1`; this adds some overhead, so leave it off for normal use.

Each press of **Speak** sends the entered text to OpenAI's `gpt-4o-mini-tts` endpoint with natural, warm, conversational delivery instructions. Nearby clauses and sentences are grouped together (up to about 220 characters) so short lines usually use one TTS request and keep their phrasing intact; longer lines split at natural punctuation/word boundaries. The laptop plays OpenAI's streamed PCM through PulseAudio while sending only compact jaw-envelope values to the browser; the server also assembles the same samples into a phrase WAV for Rhubarb analysis. The speaker path prebuffers about one second of PCM, then uses a separate playback thread with up to eight seconds of queued audio so network reads do not block PulseAudio writes; it requests a 200 ms PulseAudio latency to smooth WSLg delivery. Mouth-animation events are queued separately so a slow or disconnected iPad cannot block laptop playback; late-PCM-packet timing, PCM queue high-water depth, and producer back-pressure are recorded for diagnosis. Visitor replies are dispatched by the server and do not wait for an iPad claim or polling response. Until timed cues arrive, the avatar uses an audio-volume-driven jaw; it then switches to Rhubarb's more precise mouth shapes. First-byte, first-audio, phrase-generation, cue-ready, and audio-gap timings appear in the status line and server log. Temporary audio/dialog files are removed after analysis; generated audio is not saved to the project. Rhubarb supplies approximate animation mouth-shape cues from the actual voice recording—not exact linguistic phoneme labels—but this should stay much closer to the audio than estimating timing from text. Speech generation incurs normal OpenAI TTS usage charges.

In WSL, `./run.sh` defaults to `HOST=0.0.0.0` and `PORT=8766` so the Windows port proxy can reach the backend; the helper limits iPad access to the trusted Private Wi-Fi subnet. On non-WSL systems it stays on `127.0.0.1`. Override with `HOST=127.0.0.1 ./run.sh` for loopback-only access. Opening the clean display URL starts visitor capture automatically; add `?debug=1` to keep capture off and use the test controls.

## Avatar and animation

- **MPFB zombie model**: the bundled CC0 sample avatar has 66 facial morph targets, including visemes, jaw movement, and blinking. `assets/mpfb.glb` is compressed for download; geometry was not simplified and the morph targets are retained.
- **Floating-head treatment**: the default avatar's outfit and original ponytail are hidden, and runtime clipping trims the rigged body at a short, clean neck cutoff without a separate horizontal cap mesh. The cutoff is skin-toned and blood-free; the source head GLB is not modified. Sickly complexion, luminous milky eyes, animated ghost halo and base mist, floating light globes, stitched details, a slack expression, and the separate Otohiko wig remain. The wig follows the `Head` bone and does not alter facial morph targets.
- **Audio-timed mouth shapes and conversational reactions**: Rhubarb's basic/extended shapes are mapped to the avatar's viseme and jaw morph targets. During visitor mode, a small head tilt and slightly more attentive eyes make listening/thinking visible, while the ghost halo and base mist give a gentle pulse during listening, thought, and speech. Drag to orbit and scroll to zoom.
- **Other GLBs**: upload a compatible glTF 2.0 `.glb` from the sidebar. Facial targets such as `jawOpen` and `viseme_aa` work best; the zombie materials are applied only to the bundled MPFB avatar.
- **OpenAI voices**: choose a built-in voice and speaking speed in the sidebar. Voice character varies by selection; spoken content is AI-generated.
